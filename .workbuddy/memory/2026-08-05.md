## iOS 后台播放 + DLNA 投屏修复（提交 ae17c03）

用户反馈:iOS 无法后台播放、DLNA 投送不稳定(偶尔扫到设备、投送就消失)。

### 根因
- **后台播放**:`ios/Runner/Info.plist` 缺 `UIBackgroundModes[audio]`。代码层 `mobile_audio_service.dart` 已用 `audio_session` 的 `music()` 配 AVAudioSession category=playback,但 iOS 硬规则要求 Info.plist 声明 audio 后台模式,否则进后台即被挂起。
- **DLNA 投送消失**:`lib/provider/server/server.dart` 在 iOS/macOS 把本地流服务器绑到 `loopbackIPv4`(仅 127.0.0.1),而 `cast_provider._resolveCastUrl` 给设备的是 `http://<LAN IP>:<port>/stream/...`。局域网内渲染设备连 LAN IP 时被拒 → 拉不到流 → ping 失败 → 重连 3 次后断开 = "投送就消失"。安卓走 `anyIPv4` 故正常。
- 发现"偶尔扫到"是 SSDP 多播在 iOS 偏抖 + `discover()` 5s 后主动 `stop()` 关监听;本地网络权限 `NSLocalNetworkUsageDescription` 已声明(非主因)。

### 改动
- `Info.plist`:加 `UIBackgroundModes -> audio`;`NSLocalNetworkUsageDescription` 文案补 DLNA 发现说明。
- `server.dart`:iOS/macOS 改绑 `anyIPv4`,使 DLNA 设备能连回本机流。

### 验证
- `fvm flutter analyze lib/provider/server/server.dart`:0 issue。
- Info.plist 为原生配置,需真机/模拟器跑 `fvm flutter run` 验证后台播放与投屏;本机无法编译 iOS。

### 可选后续(未做)
- DLNA 发现 5s 后 `stop()` 关监听,可改为投屏页打开期间保持 SSDP 监听 + 定时重扫,提升稳定性。
- `cast_provider._getLanIp` 取第一个非 loopback IPv4,多网卡(含 VPN)可能取到错 IP,可优先选与网关同网段地址。

## DLNA 持续监听 + LAN IP 优选(提交 49ca50c)

用户要求把上面两个可选项都做了。

### 关键包事实(dlna_dart-0.1.1)
- `DLNAManager.start()` 内部已 `Timer.periodic(2s)` 持续发 M-SEARCH,**只要不主动 stop(),监听与周期搜索一直运行**——所以"持续监听"无需自建定时器。
- `DeviceManager.dispose()` 仅 `devices.close()`,**不清空 `deviceList`** Map。故 stop 后仍可取回底层 `DLNADevice` 供 `connect`/重连用。

### A1 DlnaDiscovery 拆 start/stop
- 新增 `start({onDeviceFound})`:启动监听后**不主动停**,重复调用安全(已在监听则忽略);`stop()`:取消订阅 + `manager.stop()` 释放 UDP,但**保留 `_deviceManager` 引用**(供 connect 取底层设备)。
- 保留 `discover()` 一次性封装(向后兼容,监听 timeout 后自动停)。
- `_mapToDevice` 去重逻辑移到调用方。

### A2 CastProvider 切持续监听
- `discover()` 改调 `startDiscovery`,状态保持 `discovering` 不自动停;用户选设备 `connect` 或关页 `disconnect`/`onDispose` 时 `stopDiscovery` 释放。
- `connect()` 成功后 `unawaited(_service.stopDiscovery())` 释放监听(保留 deviceManager 供重连)。
- `disconnect()` 加 `await _service.stopDiscovery()`。
- 监听启动失败回退一次性 `discover()`。
- `DlnaCastServiceInterface`/实现新增 `startDiscovery`/`stopDiscovery` 透传。

### B LAN IP 优选
- `_getLanIp` 优先私有网段(192.168.* / 172.16-31.* / 10.*)、排除链路本地(169.254.*)/CGNAT(100.*);多网卡/连 VPN 更可能命中真正局域网网卡;兜底取第一个非 loopback。新增 `_isPreferredLanIp` 静态判定。

### 验证
- `fvm flutter analyze` 三文件 0 issue;全量 analyze 仅 4 个既有 info(无关);`fvm flutter test` 6/6 全过(含 Lx 链路)。
- SSDP/投屏行为需在真机实测(本机无法编 iOS)。

## 系统媒体控制(锁屏/SMTC)转发到 DLNA(提交 6c93b0c)

用户问"投屏后锁屏/系统媒体控制能否控制 DLNA 设备"。结论:可行,已实现。

### 根因
- `MobileAudioService`(audio_service 的 AudioHandler,iOS/Android 锁屏)+ `WindowsAudioService`(SMTC,Windows)的 play/pause/seek/skip 回调**全部直接调本地 `audioPlayer`**(media_kit)。
- 投屏时本地播放器被 `connect()` 暂停(避免双重音频)。所以锁屏按钮控制的是"被暂停的本地播放器",DLNA 设备收不到指令;且 `PlaybackState`/`SMTC` 只从本地读状态 → 投屏后锁屏进度不动、一直显示"暂停"。

### 改动
- `mobile_audio_service.dart` / `windows_audio_service.dart`:注入 `Ref`;play/pause/seek/上一首/下一首(Windows 含 stop)在 `castProvider.isCasting` 时改道 `castProvider.notifier`(resume/pause/seek/skipToNext/skipToPrevious/stop),**非投屏路径零改动**。
- 锁屏 `PlaybackState` / SMTC 状态投屏时改以 cast 的 `isPlaying`/`position`/`duration` 为准;`ref.listen(castProvider)` 在 cast 状态变化(含 _startPositionPolling 每秒)时重推 → 锁屏进度/播放指示实时刷新。
- 切歌在投屏中保持本地暂停(`skipToNext` 后 `if(isCasting) audioPlayer.pause()`),借 `cast_provider` 监听 `activeTrack.id` 变化自动重投新曲,避免本地+设备双重出声。
- `audio_services.dart`:`MobileAudioService(ref, playback)` 透传 ref。

### 验证
- 三文件 `fvm flutter analyze`:0 issue;全量 analyze 仅 4 个既有 info;`fvm flutter test` 6/6 全过。
- 锁屏/SMTC 转发需在真机验证(本机无法编 iOS/无 Windows SMTC 环境)。

## 音量控制 + 双重音频修复(提交 3aad3b0)

用户要求"解决音量控制问题和双重音频问题"。

### 双重音频根因
投屏时 `connect()` 暂停了本地播放器,但 `playTrack`/`playTracks`/`load(swapActiveSource)` 仍会调 `audioPlayer.resume()` 或 `openPlaylist(autoPlay:true)`,把本地也拉起来 → 与 DLNA 设备同时出声。

### 双重音频改动
- `audio_player.dart`(AudioPlayerNotifier)新增 `_isCasting` getter(读 `castProvider.isCasting`);`playTrack`/`playTracks` 的 `resume()` 加 `!_isCasting` 守卫;`swapActiveSource` 的 `load(autoPlay:true)` 改 `autoPlay: !_isCasting`;`load` 内部 `openPlaylist` 的 autoPlay 改为 `autoPlay && !_isCasting`。
- `cast_provider.dart`:`build()` 新增 `ref.listen(audioPlayerProvider.select(playing))` 兜底——投屏中本地一旦恢复播放(`next==true`)立即 `svc.audioPlayer.pause()`,彻底杜绝任何路径漏网导致的双重音频。

### 音量控制改动
- `playback_page.dart`:`_PlaybackBody` 新增 `_buildVolumeControl`(cast 感知),移动端/桌面端布局均已放置(主控制与次控制之间)。
- 投屏中:滑块显示 `castState.volume`(0-100 转 0-1),拖动调 `castProvider.setVolume`;非投屏:控制本地 `audioPlayer.setVolume`。
- 本地音量用 `useState(audioPlayer.volume)` 记忆(无音量流,避免滑块跳变);`castProvider.setVolume` 已实现(写 state.volume + 调底层 DlnaControl.setVolume)。

### 验证
- 三文件 `fvm flutter analyze`:0 issue;全量 analyze 仅 4 个既有 info;`fvm flutter test` 6/6 全过。

### 已知缺口(未做)
- **锁屏/系统媒体控制的音量**:App 内滑块已接 cast,但锁屏/控制中心的音量键走 iOS 系统音量而非 DLNA 设备音量;`audio_service` 的 PlaybackState 可加 setVolume/volume(部分系统支持),属可选增强,需真机验证。
